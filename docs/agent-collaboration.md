# Agent 分工协作说明

> 适用：本工程（Unity 2D Game Jam）在 DeepSeek Harness 上的日常协作。
> 维护：人。AI 只读。

## 0. 先解决“入口在哪”

三个入口，用途不同：

1. **设置 → 通用 → 「Agent 预设」**：这里是花名册，能看到「内置」和「自定义」两组卡片，`Unity Jam` 在自定义组里。卡片上的 **「设为新任务默认」** 决定以后新会话默认用哪个。
2. **空白会话首屏的预设 chip**：新建一个还没有对话的会话时，首屏会显示当前预设，点它可以临时切换。它只影响这一次任务。
3. **工作区里点「+」**：这条路径**不弹选择器**，直接用当前默认值建会话。所以你之前“新开对话看不到选项”，不是预设没生效，而是这条入口本来就没有选择器。

要改默认，去设置；要临时试一次，去空白会话首屏。

## 1. 四个角色，各管一段

**你**负责意图和取舍：今天做什么、砍什么、什么算“可玩”、每次改动批不批。默认预设和权限只有你能改。

**主 Agent**（也就是你正在对话的这个会话）是唯一对外接口：接需求、拆任务、派子代理、汇总证据、维护待办。它不追求一次做对，而是追求“每步可验证、错了能回滚”。

**子代理**是被主 Agent 派出去的一次性劳力。`spawn` 出来的子代理上下文独立、看不到本会话历史；`fork` 出来的继承当前对话，适合“接着这段上下文再查一层”。子代理之间**不能直接通信**，所有结论必须回到主 Agent 汇总——这是“低耦合”在工程上的落地方式。

**技能**不是 Agent，是知识包。它不占常驻上下文，只在触发词命中时加载。`unity-scene-ops` 管“怎么改场景”，`unity-2d-urp-pitfalls` 管“别踩哪些坑”，`jam-verify` 管“怎么证明做完了”。改技能文件即改行为，不用重启。

**预设**也不是 Agent，是一张“这个 Agent 会什么”的配置单。换预设等于换一套工具与提示词，但不换人格。

## 2. 生命周期怎么管

**会话**：创建时选定预设，之后**不再变**。改配置只影响以后新建的会话——所以要切到 `Unity Jam`，就新开一个会话，不要指望当前会话“变身”。这也意味着：一个会话干一类活，干完就关。

**子代理**：派发 → 运行 → 返回结论 → 可以继续追问，也可以随时打断。一次性任务（“查一下这个报错”）用完即弃；长任务（“把这条玩法链路补齐”）才值得让它多轮。你不需要直接管子代理，只需要管主 Agent 的待办列表；主 Agent 跑偏时打断它，而不是去追子代理。

**技能**：没有生命周期。落在 `.dsh/skills/` 下就被发现，改完即生效。唯一的纪律是：一个技能只讲一件事，别把项目一次性事实写进去（那些属于 `AGENTS.md`）。

## 3. 任务与内容怎么合作

三条硬规则，比任何流程都重要：

1. **读可以并行，写必须串行**。同时让两个 Agent 审代码没问题；同时让两个 Agent 改同一个场景一定出事。
2. **按文件切任务，不按功能切**。“做跳跃”会跨三个文件，“把 `PlayerController.cs` 的落地检测修好”才适合派出去。
3. **一个文件同一时刻只有一个所有者**。冲突发生时不要 merge Unity 的 YAML，直接 `git restore` 重做。

交接必须结构化，四件事缺一不可：**改了什么文件、证据是什么（编译/测试/截图/日志）、还有什么风险、怎么回滚**。主 Agent 汇总时如果拿不到这四项，就应当把任务打回，而不是“大概完成了”。

验收标准只有一条：**没有证据不算完成**。截图证明“存在且没崩”，测试证明“逻辑对”，日志证明“没有隐藏异常”，三者不能互相替代；手感只能由你亲自试玩。

## 4. 当前这个会话是干什么的

这是**架构与教练会话**，不是生产会话。它的职责是：做只读体检、定方案、改配置、写文档、排查卡点、Jam 结束后做复盘。它产出的是“决定”和“文件”，不是游戏内容。

日常开发请另开 `Unity Jam` 会话：那里才有 Unity 工具、场景操作技能和验证纪律。这样做的好处是上下文干净——生产会话只装“这个功能相关的东西”，不会被架构讨论和历史决策挤爆；而这个会话保留决策脉络，随时可以回来问“当初为什么这么定”。

判断该回哪个会话：**要写玩法、搭场景、修 bug → 生产会话；要改规则、改配置、改架构、做复盘 → 本会话。**

## 5. 一天怎么用

早上开一个生产会话，用一句话说清今天的目标和“完成长什么样”。白天一次只推进一个可编译单元，每绿一次就提交。晚上跑一遍四件套，把没验证的部分写清楚，然后列出明天三件事再关会话。

三个该打断的信号：同一个错误连续出现两次、Agent 开始改你没批准的文件、Agent 说“完成了”但拿不出证据。打断不是不信任，是避免它在错误方向上越走越远。
