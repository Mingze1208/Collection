# Unity 场景操作流程

## 0. 前置：确认链路

1. 先确认编辑器在线（有 `unity_status` 就调它；没有就用工具集里的“场景层级/状态”类工具）。
2. 编辑器离线 → **停止**，报告“Unity 编辑器未运行”，不要用文件操作“模拟”场景修改。
3. 记录当前场景路径与是否已保存；有未保存改动时先提示我。

## 1. 侦察（只读）

- 获取场景层级，记录根对象名与类型。
- 确认目标对象是否存在、挂在哪个父节点下。
- 若要挂脚本：先确认脚本已编译（Console 无 error），并拿到脚本的**类型全名**。

## 2. 变更（一次一个原子操作）

按顺序，每一步都可单独失败、单独回滚：

1. 创建/定位 GameObject（明确父节点、本地坐标）
2. 加组件（明确类型与关键字段）
3. 挂脚本（用类型名，不用路径）
4. 设初始值（位置/缩放/排序层/碰撞层）

规则：
- 一次最多 3 个原子操作，然后停下报告。
- **绝不**直接编辑 `.unity` / `.prefab` 的 YAML。
- **绝不**创建或删除 `.meta`。
- 修改已有预制体实例前，先说明“这是实例覆盖还是改源预制体”。

## 3. 保存与验证

1. 保存场景（有 `save_scene` 类工具就调它）。
2. 截一张 Scene 或 Game 视图。
3. 读一次 Console 新增的 warning/error。
4. 按下面格式输出：

```
改动：
- 新增 Player（SpriteRenderer + Rigidbody2D + PlayerController）
- 挂载 Assets/_Project/Code/Runtime/Player/PlayerController.cs
证据：
- 场景已保存 ✓
- 截图 ✓（附路径）
- Console：0 error / 1 warning（内容）
风险：
- Rigidbody2D 的 gravityScale 仍为默认 1，2D 俯视角可能需要 0 —— 需你确认
```

## 4. 失败处理

- 任一工具报错 → 立即停止，报告原始错误文本，**不要重试第三次以上**。
- 半成品状态：告知我“场景处于半改状态”，并建议 `git restore` 而不是“再改回去”。
